# Protocol: MIK-0 retrieval

This protocol was written before the held-out evaluation. No fine-tuning, external web search, or task-specific answers are included in the model prompt. Model and tokenizer snapshots must be recorded by resolved revision. Use greedy decoding on CPU, float32, max 96 generated tokens per decision, and at most six decisions including the final answer. Use the same question, prompts, model settings, world and budget in both tool conditions. No output repair or hidden retries.

Models: `HuggingFaceTB/SmolLM2-135M-Instruct` and `HuggingFaceTB/SmolLM2-360M-Instruct`. These are two sizes in one family, not size-matched controlled experiments: pretraining and instruction tuning may differ. Load each frozen. Model downloading requires network, but task execution uses the local generated world.

Use seed 10728 for smoke tests and 20261029 for the final world, each with 100 tasks. Each task has a distinct random chain of four typed facts and random 48-bit identifiers, shuffled records, and a natural-language question. The evaluator holds the answer key; the model sees only the question and observations. Seeds make the generated data reconstructible, not cryptographically secret. The final seed was not used to tune the prompt. There are 2,000 unrelated distractor facts, but one fact per entity and no distracting facts for a queried subject; this is a deliberately simplified initial environment.

Run each model with search enabled and disabled on the same 100 tasks. With tools disabled, a search yields an explicit disabled error; the prompt is unchanged. The no-tools condition has no access to the randomly generated facts, so near-zero accuracy is expected and is a sanity check rather than a meaningful general reasoning comparison. Compare a handwritten four-relation traversal with the same database enabled/disabled; this baseline is task-specific and must never be counted as learned kernel intelligence.

Predeclared exploratory success criterion: at least 50/100 answers correct **and** supported by all four observed record IDs in a model's enabled condition. This threshold is a feasibility gate, not a statistical proof of minimality. Report both plain answer accuracy and evidence-supported accuracy. Describe failures, exact counts, Wilson 95% intervals for plain accuracy, and all four conditions. Report paired per-task outcomes when making model/condition comparisons; no causal claim about model size from these two models alone.

Generate a new world for independent replication. All traces, errors, budgets and incomplete runs must be retained and identified, not silently discarded. Reports must distinguish smoke tests from final evaluation and not call an interrupted or smaller run a 100-task evaluation. The current measure tool implements a fixed relation solely as an interface fixture; discovery, revised hypotheses, misleading evidence, task composition, true held-out rule families, and persistent learning are not yet evaluated.
